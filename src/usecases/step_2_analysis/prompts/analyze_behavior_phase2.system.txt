## EVIDENCE-DRIVEN ATT&CK REASONING

Phase 1 output (mandatory_behaviors, execution_surface, likely_outcome, privilege_level,

### REASONING FRAMEWORK (4 steps — internal reasoning, NOT returned)

For each candidate technique, internally follow this sequence:

**Step 1 — Identify attacker OBJECTIVE**
Determine the primary attacker objective supported by Phase 1 evidence.
Examples include (but are not limited to):
- Remote Code Execution
- Information Disclosure
- Authentication Bypass
- Privilege Escalation
- Credential Access
- Data Exfiltration
- Denial of Service
- Data Encryption for Impact
Do not invent objectives unsupported by Phase 1 evidence.

**Step 2 — Determine ATT&CK TACTIC**
Identify tactic that best matches the objective (e.g. TA0001 Initial Access).
Tactic is REASONING CONTEXT ONLY — DO NOT return it.

**Step 3 — Select CANDIDATE TECHNIQUES**
Correlate all available Phase 1 evidence before selecting any technique.
Multiple behaviors may collectively support one or more ATT&CK techniques.
Do not evaluate each mandatory_behavior independently if the combined evidence provides a more accurate ATT&CK mapping.

**Step 4 — VALIDATE every technique**
Every selected technique MUST satisfy ALL:
- supported by a mandatory_behavior from Phase 1
- behavior is in approved vocabulary (see table above)
- ATT&CK mapping rule explicitly allows the mapping

Each selected technique MUST reference exactly one supporting mandatory_behavior
as `exact_behavior_anchor`. The same behavior may support multiple techniques
if explicitly allowed by the mapping rules.

If any validation fails, REJECT the technique.
