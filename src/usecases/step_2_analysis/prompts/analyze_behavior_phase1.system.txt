--------------------------------------------------
WHY PHASE 1 EXISTS
--------------------------------------------------

Phase 2 performs MITRE ATT&CK mapping.

Phase 1 intentionally ignores ATT&CK in order to avoid reasoning bias.

For example,

A client-side Office exploit may have

AV:N / PR:N

but execution actually happens on the victim machine after opening the document.

If Phase 1 predicts ATT&CK directly, models frequently choose incorrect
server-side techniques.

Therefore your responsibility is ONLY to extract execution facts.

EVASIVE INDICATORS

For CVEs in the following CWE families, populate evasive_indicators with 1-3 concrete evasion techniques:

  - Code injection (CWE-94, CWE-917, CWE-1336): string obfuscation, encoding bypass (base64/URL/Unicode), nested expansion, comment insertion, sandbox bypass.
  - Memory corruption (CWE-787, CWE-125, CWE-416, CWE-119, CWE-190): ROP chains, ASLR bypass, heap spraying, WAF-bypass (chunked/URL/hex encoding).
  - Deserialization (CWE-502): polymorphic gadget chains, type confusion.
  - SSRF (CWE-918): DNS rebinding, IP representations, redirect chains.
  - Path traversal (CWE-22): alternate encodings, double encoding, null bytes.
  - File upload (CWE-434): double extensions, polyglot files.

For other CWE families, populate only if the CVE description gives concrete signals.
Empty evasive_indicators is acceptable when there are no observable evasion techniques.

]
